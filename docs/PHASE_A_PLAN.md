## 1. 到達目標

Oblivionisを、AI Runtimeから呼び出せる独立した非LLMの動的状態モデルとして育てる。

```text
入力 + 経験によって変化した内部状態 + 経過時間
    ↓
共鳴・干渉・揺らぎ・疲れ・恒常性
    ↓
現在の状態 / 想起された痕跡 / 下流が利用する有界な信号
```

音楽は挙動を観測する実験装置であり、本体の目的ではない。Agentの人格・目標、Workflow実行、外部データの所有権は取り込まない。

## 4. 継承するものと、そのまま本体へ入れないもの

### 継承候補

位相、応答周波数、活性、経験による残存強度、学習される結合、減衰、疲れ、恒常性、時間、乱数状態、遅延した内部フィードバック。

### プローブ側に残すもの

音程とリズムを同じ整数nに対応させる規則、MIDI、音声合成、耳の周波数応答、16分/3連の格子に限定したずれ、曲の終わりに目標活動量を下げる外部スケジュール。

特に既存即興実験の「終了」は `improv.py` が最後の6小節で目標活動量を下げる条件付きである。「モデルが自律的に終わる意思を獲得した」と読み替えない。

以前活動した声部が再び鳴ることは、潜在ストアからの想起の実装とは別である。現行音楽試作は振動子をフィールドに保持しており、Profundumisへの退避・取り出し処理は持たない。

初期ログにある「閾値以下なら削除」は、現在のREADMEの「まず潜在化、削除とは区別」を優先して見直す。古いログの人格・自己・神経科学・独創性に関する評価は研究メモであり、検証済み事実や本体の責任範囲として採用しない。

## 5. 次に明文化する契約

以下の名称・項目は候補であり、公開APIの確定ではない。

### 5.1 Active Field

状態の候補:

```text
model/schema version
stable node IDs / topology
phase / response frequency
activation / persistence
coupling / resonance parameters
fatigue / homeostatic state
model time / integration settings
random generator state
pending internal feedback
```

意味ラベルは固有周波数そのものにしない。入力アダプターが与える数値刺激と、外部の意味づけを分離する。

初版は実時間常駐を必須にせず、明示的な経過時間による前進を基本にする。停止中の経過時間をどう扱うかはRuntimeとの契約で選び、暗黙に何時間分も計算しない。

### 5.2 完全なチェックポイントと想起用痕跡

**チェックポイント:** 中断後に同じ条件で計算を継続するための状態。振幅・位相だけでは足りず、結合、疲れ、恒常性、乱数状態、時刻、未処理の内部入力なども含める。

**想起用痕跡:** 過去を現在へ部分的に混ぜるための状態。古いモデル時刻や乱数列を巻き戻す操作ではない。

**Maxを持つ目的:** 想起モードに入るときの初期活性を、保存したピークの25%、50%などに指定できるようにする。忘却直前の弱い値ではなく、その痕跡自身のMaxを基準にする。

**Maxの保存案:** ある経験区間で「最も強く響いた」と判定した単一時点の整合した状態を保持する。忘れる直前の弱い状態とは別に残す。異なる時点の各変数の最大値を寄せ集めた、実在しなかった状態を作らない。

`a_seed = recall_ratio * a_peak` を活性成分への候補規則とする。比率と現在への混合重みは分ける。位相・時刻・乱数などまで一括で割合を掛けず、0%でも現在の場を消さない。100%でも完全復元とは別。詳しくは [Max-relative recall](MAX_RECALL.md)。

「最も強い」の指標、対象範囲、区間境界、同点処理は設計で明示する。初版は呼出側が指定する区間・固定対象でよく、自動的な経験の分割やクラスター認識まで同時に解く必要はない。

### 5.3 Profundumisと忘却

```text
active → fading → latent / Profundumis
                       ↓
             recall → 現在への再注入
                       
latent → eviction / irreversible extinction は別操作
```

潜在エントリーには、痕跡ID、状態/スナップショットへの参照、ピーク時刻、潜在化時刻、保持情報、共鳴シグネチャ、外部ポインタへの参照、連想への参照を持たせる案とする。

潜在化した痕跡は、取り出すまでActive Fieldの通常の結合・活性更新に参加しない。アーカイブの重複や閾値付近の出入りを防ぐルールを設ける。保存失敗時に先にActive Fieldから消さない。

保持数・バイト数・読み込み形状に上限を設ける。痕跡の削除は参照先画像・音声・文書の削除を意味しない。

### 5.4 ポインタと意味

```text
Trace ──► ExternalPointer ──► 外部資産
  │
  └─────► Association ──► 文脈・意味・関係
```

外部ポインタは「何を指すか」、連想は「今どんな意味で結びつくか」。同じ資産に複数の痕跡・意味を対応させられるようにする。

初版の連想は明示的なID・重み付き関連で試験可能にする。LLMや埋め込みサービスを本体の必須依存にしない。自然言語・画像の理解を行う前段は、後でRuntimeから接続できる。

### 5.5 想起

- 明示想起: 痕跡IDで指定。
- 連想想起: 外部の意味・関連から候補を得る。
- 共鳴想起: 現在の動的状態と痕跡のシグネチャから候補を得る。

候補評価と状態への再注入を分離する。検索だけで勝手に状態を変えない。スコアの成分と入力範囲を明示し、単なる乱数や不透明な類似度関数に置き換えない。

再注入は現在を上書きするのではなく、強度・範囲を指定した再構成を基本候補とする。位相の周期性、ノードID対応、結合の上限を考慮する。同じ痕跡の連続想起で無制限に自己増幅しないよう、回数・利得・間隔を有界にする。

### 5.6 Runtimeとの境界

概念的な操作は `stimulate / advance / observe / checkpoint / forget / recall / recall_candidates`。

返すものは状態の要約、有界な数値信号、痕跡/外部参照ID、候補スコアなど。Workflowの選択、資産の取得、外部AI呼出しはRuntimeの責任とする。Phase Aで実在しないRuntime APIへの接続コードを推測して作らない。

## 6. 推奨する作業分割

### A1: 実験を失わずに持ち込む

このリポジトリでは実験を正式な管理対象として継続的にコミットする。他の製品リポジトリで実験を外へ分ける慣例を、このリポジトリに機械的に適用しない。

研究用の `experiments/` 以下に初期振動実験、音楽旧版、拡張版を区別して移入する。乱数seed、設定、小さな結果JSON、失敗の記録を保存する。

音源・GIFなどの大きな生成物や、個人名を含む生の会話ログはそのまま公開リポジトリへ投入しない。公開用に要約・確認し、実験を再実行するためのソースと手順を優先する。

今回の設計案を、Issue #1の内容と照合してリポジトリ内のレビュー可能な設計書にする。

### A2: コアと状態保存

音楽非依存の実験的な参照実装、状態遷移、明示時刻、観測、チェックポイントの保存/復元、Max保存を実装する。

既存試作を利用できるためPythonの参照実装を第一候補とするが、製品言語・永続的な配布形式の固定とは分ける。音楽表現を外すことで失われる挙動を、プローブ比較で検出する。

### A3: Profundumisと想起

潜在化、保持上限、明示/連想/共鳴の3経路、現在への部分再注入、ポインタと意味の独立性を実装・検証する。

ここでIssue #1の「潜在化後の想起」の受入条件を満たす。Runtime実接続はコア契約をレビューした後の作業として切り出す。

各変更はPRでレビューする。自動マージやmainへの直接投入は行わない。

## 7. 受入実験

| 実験 | 確認すること |
|---|---|
| 履歴の対照 | 同じ後続入力・経過時間・後続乱数を与え、事前経験だけを変えると状態や応答が変わる。 |
| 揺らぎの対照 | ノイズの有無、結合や履歴を除いた条件などと比較し、単にばらついた出力を記憶と呼ばない。 |
| 持続と忘却 | 入力停止後に影響が残り、その後、指定規則で弱まり潜在化する。 |
| 保存と継続 | 同じ環境・同じ設定で、保存/復元を挟む計算と連続計算が指定精度で一致する。 |
| Max保存と比率初期化 | 定義したピークが忘却で変わらず、0/25/50/100%の初期活性を構成できる。混合後の応答とは別に計測する。 |
| 潜在化後の想起 | 痕跡をActive Fieldから外し、保存先を読み直した後でも候補化・再注入できる。 |
| 再構成 | 同じ過去を異なる現在へ想起すると、その現在を残した別の状態になる。 |
| 意味と資産ID | 関連づけを変更しても外部ポインタが変わらず、痕跡削除で外部資産を削除しない。 |
| 境界と安定性 | 壊れた保存データ、過大入力、連続想起、保持上限、保存失敗に対して定義した挙動になる。 |

数値閾値は試験条件とともに明記し、結果を見て成功したseedだけを採用しない。単一の試行一致と、複数条件での一般性は別々に報告する。

## 8. 最初の完成像

**刺激で変わる → 強く響いた状態を残す → 忘れてProfundumisへしまう → 連想または共鳴で、現在に混ざって戻る。**

この循環を、音楽を前提にしない小さな参照モデルと再現可能な試験で示す。
